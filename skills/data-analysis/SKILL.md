# Trusted Procurement Agent

기업 구매·조달 담당자가 **오늘 먼저 볼 품목**을 정해 주는 스킬이다.
61개 품목을 매일 다 볼 수 없는 사람에게 **오늘 볼 것만** 골라 준다.
몇 개가 될지는 우리가 정하지 않는다 — 「산지·도매·소매 중 한 단계라도
평년보다 높은가」로 고르므로 **0개인 날에는 아무것도 나오지 않는다.**

**결정을 대신하지 않는다.** 계약단가·재고·발주 일정을 모르기 때문이다.
「무엇을 먼저 검토할지」까지만 말한다.

---

## 🔴 타임리에서 부를 때 — 이 한 줄이면 된다

사람이 「오늘 브리핑 만들어 줘」라고만 해도 아래를 그대로 한다.
**아무것도 되묻지 않는다.**

```
TPA_DATA_DIR=./tpa python3 .pi/skills/trusted-procurement-agent/scripts/agent.py
```

🔴 `export` 를 따로 치고 다음 줄에서 실행하면 안 된다. 명령마다 셸이 새로
   뜨면 그 export 가 날아가고, 상태가 매 턴 지워지는 `.pi/` 안에 쓰인다.

출력 첫 줄의 상태로 갈라진다.

| 상태 | 할 일 |
|---|---|
| 「변화 없음」·「실패」 | **화면을 만들지 않는다.** 출력만 옮긴다 |
| 그 밖 | 아래 한 줄로 화면을 띄운다 |

```
create_artifact(from_path="tpa/output/report.html", title="오늘 먼저 볼 것")
```

🔴 **경로 앞에 `./` 를 붙이지 않는다.** 워크스페이스 기준 상대경로다.
   `./tpa/…` 로 주면 파일을 못 찾고, 그러면 「그럼 내가 만들자」로 넘어간다.

🔴 **HTML 을 새로 쓰지 않는다.** 그 파일이 이미 완성된 화면이다.
   품목 표를 만들지 않고, **품목 이름을 바꾸지 않는다.** 응답에는
   위 명령의 출력을 **그대로** 코드블록에 붙이고, 그 밖의 것을 쓰지 않는다.
   사람이 읽을 요약이 필요하면 `tpa/output/report.txt` 를 그대로 옮긴다.

🔴 인증키가 없어도 `request_env_var` 를 부르지 않는다. 그냥 진행한다 —
   동봉 스냅샷으로 전 과정이 돈다.

## 언제 쓰나

- 매일 아침 식자재 시세 점검이 필요할 때
- 특정 품목이 평소와 다르게 움직이는지 확인할 때
- 가격이 **산지에서 올랐는지 유통에서 올랐는지** 구분해야 할 때
- 같은 물건을 **어느 도시에서 더 싸게** 살 수 있는지 볼 때

## 준비

### 1) 인증키

[공공데이터포털](https://www.data.go.kr/)에서 발급받은 키를 환경변수로 넣는다.
**키를 파일에 저장하지 않는다.**

```bash
export DATAGO_KEY="발급받은키"
```

타임리에서는 **사람이 대화로 부를 때** `request_env_var` 로 `DATAGO_KEY` 를 요청한다.
🔴 **예약 실행에서는 묻지 않는다** — 아무도 없는 시각에 사람을 기다리면 루프가 멈춘다.

> 🔑 **인증키가 없어도 동작한다.** `sample-data/` 의 수집 스냅샷으로
> 전 과정이 재현된다. 다만 「오늘」이 스냅샷 시점으로 고정된다.

### 2) 데이터를 쓸 위치

```bash
export TPA_DATA_DIR="./tpa"     # 생략하면 스킬 폴더 안에 쓴다
```

🔴 **타임리에서는 반드시 지정한다.** `.pi/skills/` 는 매 턴 초기화되므로
그 안에 상태를 쓰면 **다음 주기에 사라지고 중복 감지가 작동하지 않는다.**
워크스페이스 루트 아래(`./tpa` 등)를 지정해야 자동 sync 로 생존한다.

### 3) 파이썬

**주 실행 경로(수집·판정·산출)는 표준 라이브러리만 쓴다. 설치할 것이 없다.**
`requests` 를 쓰지 않는다.

단 `scripts/import_code_tables.py` 하나만 `openpyxl` 을 쓴다 — 참고문서 엑셀을
CSV 로 옮기는 준비 작업이며, **결과 CSV 가 이미 동봉돼 있어 실행할 필요가 없다.**

## 사용법

### 한 번만 돌리기

```bash
python scripts/agent.py
```

한 주기를 완주하고 무슨 일이 있었는지 출력한다.
**시세가 어제와 같으면 API 호출 1회로 끝난다** — 수집도 판정도 하지 않는다.

### 반복 확인

```bash
python scripts/agent.py --loop 3            # 3회 연속
python scripts/agent.py --loop 24 --every 3600   # 1시간 간격 24회
```

### 부분만 돌리기

```bash
python scripts/collect.py [기준일 YYYYMMDD]   # 수집만
python scripts/run.py                         # 수집본으로 판정만
python scripts/render.py                      # 판정 JSON 으로 화면만
```

## 산출물

```
$TPA_DATA_DIR/output/
  report.json    판정 결과. 숫자에 대한 유일한 원본
  report.html    브리핑 화면 (타임리 create_artifact 에 그대로 넣는다)
  report.txt     같은 내용의 텍스트. 화면이 깨져도 숫자는 남는다
```

타임리에서 화면을 띄울 때:

```
create_artifact(from_path="tpa/output/report.html",
                title="오늘 먼저 볼 것")
```

## 무엇을 어떻게 판정하나

### 기준가 — 「평소」의 정의

**같은 품목·같은 도시·같은 품종·같은 등급·같은 달**의 과거 5년 관측이다.
계절이 지배하는 품목이라 **같은 달끼리만** 비교한다.

### 이상 판정 — 🔴 임의 임계치를 쓰지 않는다

과거 관측을 늘어놓고 **올해가 몇 번째인지** 센다.
1번째면 「가장 높음」이다. *"몇 % 넘으면 이상"* 같은 선을 우리가 정하지 않는다.

### 우선순위

**조사 도시 중 최근 5년 같은 달 최고가인 도시가 가장 많은 순서.**
개수가 아니라 **비율**로 본다 — 조사 도시가 많은 품목이 무조건 앞서면 안 된다.
**절대 가격과 무관하다.** 10만원짜리 사과보다 1천원짜리 고추가 앞설 수 있다.

### 유통 3단계

```
산지(공판장 낙찰가) → 도매(중도매 조사가) → 소매(소비자가)
```

각 단계를 **자기 평년과만** 비교한다. 관측 단위가 달라 서로 빼거나 나누지 않는다.
어느 단계에서 처음 벌어졌는지는 **관측**이지 원인 규명이 아니다.

## 사람이 없어도 도는 이유

| 상황 | 동작 |
|---|---|
| 시세가 어제와 같음 | 호출 1회로 끝. 중복 처리하지 않는다 |
| API 가 죽음 | 3회 재시도 → 실패를 기록하고 **다음 주기에 재시도** |
| 트래픽 한도 초과 | 기록하고 다음 주기로 이월 |
| 수집이 실패 | 기존 수집본으로 판정만이라도 시도 |
| 상태 파일이 깨짐 | 빈 상태로 시작 |
| 확인이 필요한 사안 | **멈추지 않는다.** 산출물에 표시만 한다 |

검증: `python tests/test_loop.py` — 위 상황을 일부러 만들어 확인한다.

## 답하지 않는 것

- **살지 말지** — 계약단가·재고·발주 일정을 모른다
- **앞으로 오를지** — 선행성을 측정하지 않았다. 예측하지 않는다
- **왜 올랐는지** — 어느 단계에서 벌어졌는지까지만 말한다
- **어느 점포가 싼지** — 우리가 아는 것은 **도시별 조사가격**이지 점포 가격이 아니다
